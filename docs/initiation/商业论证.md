# 商业论证（Business Case）

| 项目名称 | 资产经营管理系统 |
|----------|------------------|
| 文档版本 | V1.0 |
| 编制日期 | 2026-08-26 |

---

## 1. 执行摘要

本项目通过建设 **三端一体化资产经营管理系统**，将经营性资产从登记、招租、签约、收费到巡检、退租、处置的全流程线上化，支撑国资监管与经营考核。预期在 **12–18 个月** 内通过提升出租率、收缴率与降低人工成本，实现可衡量的投资回报，并降低合规与信用风险。

## 2. 问题陈述（现状痛点）

| 痛点 | 业务影响 |
|------|----------|
| 台账分散、账实不符 | 资产底数不清，盘活无依据 |
| 招租签约线下 | 周期长、合规举证难 |
| 收费对账手工 | 收缴率低、欠费难追 |
| 退租清场无标准 | 保证金纠纷、空置衔接断裂 |
| 预警靠人工 | 合同到期、欠费响应滞后 |
| 报表滞后 | 集团考核缺乏数据支撑 |

## 3. 方案概述

建设 **资管云平台**：

- PC 管理中枢 + 租户小程序 + 外勤工作端
- 定价引擎、合同全生命周期、业财对账、合规备案
- 与微信、发票、电子签、GIS、ERP 集成

详见 [需求规格说明书](../需求规格说明书.md)、[概要设计说明书](../design/概要设计说明书.md)。

## 4. 可选方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 自研本系统 | 贴合国资流程、可扩展、数据自主 | 建设周期与投入 | **推荐** |
| B. 通用物业 SaaS | 上线快 | 国资招租/备案/权证弱定制 | 不满足监管 |
| C. 维持 Excel+OA | 无建设成本 | 不可扩展、风险高 | 不可持续 |
| D. 重型 ERP 单模块 | 财务强 | 租控、外勤、小程序弱 | 仅作财务辅系统 |

## 5. 收益分析（定性 + 量化框架）

### 5.1 直接收益

| 收益项 | 说明 | 量化方式（上线后 12 个月） |
|--------|------|---------------------------|
| 收缴率提升 | 自动出账、催缴升级、线上缴费 | 收缴率 ↑ 3–8%（基线对比） |
| 出租率 / 盘活率 | 空置盘活任务、公开招租 | 空置面积 ↓、盘活转化率可统计 |
| 人力节约 | 减少重复录入、对账、催缴人工 | 财务/运营工时 ↓（人天/年） |
| 纠纷减少 | 清场验收、保证金流水留痕 | 退租纠纷件数 ↓ |

### 5.2 间接收益

- 国资监管检查材料一键导出，降低合规成本
- 数据驾驶舱支撑投资决策
- 客商信用与黑名单降低坏账风险
- 电子签、发票线上化改善租户体验

### 5.3 成本估算（框架）

| 成本类别 | 说明 |
|----------|------|
| 建设成本 | 人力 + 第三方实施（一次性） |
| 基础设施 | 云资源年费 |
| 运营维护 | 运维人力、版本迭代（年化） |
| 培训变更 | 用户培训、组织切换 |

*具体金额由业主预算表填写。*

### 5.4 ROI 计算模板

```
年化净收益 = 增收（收缴↑ + 出租↑）+ 降本（人工↓ + 纠纷↓）− 年化运营成本
投资回收期 = 建设总投入 / 年化净收益
```

## 6. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 用户采纳率低 | 中 | 高 | 培训、工作端减负、领导驾驶舱价值可见 |
| 数据迁移失败 | 中 | 高 | 分批迁移、并行试运行 |
| 第三方接口不稳定 | 中 | 中 | 沙箱预演、降级策略（应急预案） |
| 范围膨胀 | 高 | 中 | SRS 基线、变更委员会 |

## 7. 成功标准

与 [项目章程](./项目章程.md) 及 SRS §10 验收标准一致：

- 十三条业务闭环验收通过（SRS §4.27）
- 200 在线性能达标（见性能测试报告）
- UAT 签字、系统交接完成

## 8. 结论与建议

**建议批准立项并按 W1→W3 分期投入**，优先交付 P0 运营闭环（定价、合同、退租、招租、盘点、盘活），再扩展业财与智能化能力，以控制风险并尽早产生经营收益。
