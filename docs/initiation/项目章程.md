## 1. 项目背景与动因

地方国资国企、城投集团对经营性资产（房产、土地等）的管理长期依赖台账分散、流程线下、收缴与监管数据割裂。上级对 **资产盘清、经营提效、合规安全、监管有效** 提出明确要求，亟需建设统一的资产经营管理系统。

## 2. 项目目标

| 目标维度 | 具体目标 | 衡量指标（上线后） |
|----------|----------|-------------------|
| 盘清 | 全域资产一本账、账实相符 | 账实相符率、台账完整率 |
| 提效 | 招租—签约—收费线上化 | 出租率、收缴率、线上缴费占比 |
| 合规 | 权证、合同、审批留痕 | 备案材料可追溯率 |
| 监管 | 驾驶舱、预警、报表 | 预警闭环率、报表及时性 |

建设模式：**资产一本账、布局一幅图、管理一张屏、资债全局览**。

## 3. 项目范围

### 3.1 在范围内

- PC 管理后台（Web）
- 微信小程序用户端（承租方）
- 微信小程序工作端（外勤运维）
- 统一 API 与第三方集成（微信、支付、发票、电子签、GIS、ERP）
- SRS V2.4 全量功能（P0 / P1 / P2 + 十三条业务闭环 + 收费算法与期初迁移）

### 3.2 不在范围内

- 客户现有财务系统内部核算规则改造（仅对接凭证）
- 非本系统承担的硬件采购与机房建设（可提供建议配置）

## 8. 风险与假设

| 风险 | 缓解 |
|------|------|
| 需求蔓延 | SRS 基线 + 变更流程 |
| 第三方联调延迟 | 尽早沙箱对接、Mock |
| 历史数据质量差 | 盘点与清洗专项 |
| 网络环境限制 | 部署前网络评估 |

**假设**：业主提供业务规则确认人；生产网络满足 SRS 非功能要求。

## 9. 治理与变更

- 需求变更须更新 SRS 版本并评审
- 技术重大变更须补充 ADR
- 周例会同步进度；月度向发起人汇报
