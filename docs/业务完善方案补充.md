| 文档版本 | V1.1 |
|---------|------|
| 编制日期 | 2026-08-26 |
| 定位 | 业务专家视角补强（**已全部并入 SRS V2.0**） |
| 关联文档 | [需求规格说明书.md](./需求规格说明书.md) V2.0 |

---

## 1. 总体判断

现有 SRS 已覆盖 **台账—招租—租赁—合同—收费—催缴—巡检维修—处置** 主链路，三端分工清晰，适合作为一期建设基线。

从国资国企资产运营实务看，仍存在 **「有功能点、缺业务规则」「有单据流、缺经营闭环」「有预警、缺处置闭环」「有收缴、缺业财闭环」** 四类典型缺口。若不补齐，系统易沦为「录单工具」，难以支撑 **盘活率、收缴率、合规率** 三类核心 KPI。

本补充方案遵循原则：

1. **先闭环、后扩展**：每条补充必须说明「触发条件 → 业务动作 → 状态变更 → 下游联动 → 考核指标」。
2. **复用现有模块**：优先在合同、收费、任务、预警上扩展，避免重复建模块。
3. **分期可落地**：P0（一期必做）、P1（二期强化）、P2（监管/智能化）。

---

## 2. 目标业务闭环（完善后）

完善后的端到端闭环如下，新增环节以 **【补】** 标注：

```mermaid
flowchart LR
  A[资产接收/登记] --> B[权证与价值建档]
  B --> C[租控与定价基准]
  C --> D[招租/遴选]
  D --> E[签约审批]
  E --> F[租金计划生成]
  F --> G[履约收费]
  G --> H[发票与对账]
  H --> I[巡检与报修]
  I --> J{合同到期/退租?}
  J -->|续签| E
  J -->|退租| K【补】清场验收]
  K --> L【补】保证金结算]
  L --> M{闲置?}
  M -->|是| C
  M -->|否| N[处置/退出]
  N --> O[档案归档]

  G -.欠费.-> P【补】催缴升级]
  P --> G
  C -.预警.-> Q【补】盘活任务]
  Q --> D
```

**闭环校验标准（验收用）：**

| 闭环 | 校验点 |
|------|--------|
| 经营闭环 | 任一在租资产可追溯到：定价依据 → 合同 → 账单 → 实收 → 发票 |
| 空置闭环 | 任一空置资产有：空置原因 → 盘活方案 → 招租记录 → 结果 |
| 退租闭环 | 任一退租有：清场单 → 费用结算 → 保证金处理 → 租控状态回写 |
| 风险闭环 | 任一预警有：规则 → 触发 → 责任人 → 处理动作 → 关闭/升级 |
| 监管闭环 | 关键事项可导出备案材料（公开招租、处置、大额减免等） |

## 3. 缺口诊断与最优补充方案

### 3.1 经营计划与预算闭环 【P1】

**现状缺口**

- 设计稿出现「预算管理」Tab，SRS 仅作预留，未定义 **收入目标、空置压降目标、收缴率目标** 与实际的对比机制。
- 经营看板多为结果展示，缺少 **「计划—执行—偏差—督办」** 管理动作。

**业务风险**

- 无法回答「本月未达标是空置还是欠费」「哪个项目/公司拖后腿」。
- 集团对子公司的经营考核缺乏系统抓手。

**最优方案**

| 能力 | 说明 |
|------|------|
| 年度/月度经营计划 | 按公司、项目录入：目标出租率、目标收缴率、目标经营收入、空置面积压降目标 |
| 计划分解 | 计划可分解到项目、资产类型；支持导入与版本留痕 |
| 偏差分析 | 看板增加「计划 vs 实际」：收入偏差、空置偏差、收缴偏差 |
| 督办任务 | 偏差超阈值自动生成 **盘活督办任务**（接入任务中心），指定责任人与完成时限 |
| 考核报表 | 按公司/部门输出月度经营考核表（可导出） |

**闭环联动**

```
经营计划 → 日常运营产生实际数据 → 看板偏差计算 → 超阈值预警 → 督办任务 → 招租/催缴/调价动作 → 指标回升
```

**需求编号建议**：FR-PLAN-001 ~ FR-PLAN-004

---

### 3.2 定价与租金规则引擎 【P0】

**现状缺口**

- 已有「租金类型、缴费周期、调价、减免」，但缺少统一的 **租金计划生成规则** 与 **定价合规校验**。
- 国资招租常要求：**评估底价、备案价、成交价** 三者关系可追溯。

**业务风险**

- 手工录入易出错；免租期、递增、阶梯价、按面积/按套计价混用时账单混乱。
- 低于底价签约缺乏系统拦截或特批留痕。

**最优方案**

| 规则类型 | 业务规则 |
|----------|----------|
| 定价基准 | 资产档案维护：评估租金、备案底价、市场参考价（可挂评估申请结果） |
| 计租方式 | 固定月租 / 年租 / 按面积 / 按套 / 面议（面议须审批后转固定） |
| 递增规则 | 按年递增比例或固定增幅；支持阶梯租金（第 1–3 年不同单价） |
| 免租规则 | 装修免租天数或免租月数；免租期不计收但合同期连续 |
| 保证金规则 | 按租金倍数或固定金额；与合同模板变量联动 |
| 账单计划 | 合同审批通过后 **自动生成全周期缴费计划**（收费大厅「租金缴费计划列表」的数据源） |
| 合规校验 | 签约价 < 底价时：阻断或触发「超低价审批」流程 |

**闭环联动**

```
定价基准（权证/评估）→ 招租挂牌价 → 签约录入 → 规则引擎生成计划 → 收费大厅出账 → 调价/减免回写计划
```

**需求编号建议**：FR-PRICE-001 ~ FR-PRICE-006

---

### 3.3 公开招租与客商准入 【P0】

**现状缺口**

- 招租管理侧重「发布列表」，缺少国资场景常见的 **公开招租流程**：公告期、报名资格审查、保证金、开标/评议、结果公示。
- 租户管理侧重联系人信息，缺少 **客商信用与黑名单**。

**业务风险**

- 公开招租合规性难以证明；劣质租户重复入驻、欠费逃逸。

**最优方案**

**A. 公开招租流程（可配置开关）**

| 阶段 | 要求 |
|------|------|
| 招租公告 | 公告标题、租期、面积、挂牌价/面议、报名截止日、公示期 |
| 报名受理 | 用户端报名 + 材料上传（身份证/营业执照、授权书） |
| 报名保证金 | 可选：报名保证金缴纳与退还规则（未中标退还） |
| 资格审查 | 招租审批扩展：资格符合/不符合、意见留痕 |
| 结果确认 | 中标/未中标通知；中标后一键发起「添加租赁」 |
| 公示归档 | 公告、报名名单、审批记录打包备案 |

**B. 客商准入与信用**

| 能力 | 说明 |
|------|------|
| 租户信用档案 | 历史欠费次数、退租纠纷、报修恶意记录、综合评分 |
| 黑名单 | 黑名单租户禁止新签约；签约时自动校验 |
| 关联主体识别 | 同一证件号/法人多账号关联提示 |
| 续租优先 | 信用良好租户合同到期前自动进入「续签提醒」队列 |

**闭环联动**

```
空置资产 → 公开招租公告 → 报名与审查 → 中标 → 租赁签约 → 租户信用累积更新
```

**需求编号建议**：FR-TENDER-001 ~ FR-TENDER-005，FR-TENANT-CREDIT-001

---

### 3.4 合同全生命周期变更 【P0】

**现状缺口**

- 合同管理覆盖签约、审批、退租退费，但运营中高频的 **续签、转租、换租、主体变更、面积变更、提前解约** 缺少标准流程。
- 「租金调价」在收费侧，与合同版本关系不清晰。

**最优方案**

| 变更类型 | 流程要点 | 系统联动 |
|----------|----------|----------|
| 续签 | 到期前 N 天提醒 → 续签草稿（可调价）→ 审批 → 新合同/原合同延期 | 旧合同终止或关联；新缴费计划 |
| 转租 | 原租户退租清场 + 新租户签约；或三方变更协议 | 租控承租人变更 |
| 主体变更 | 同一资产承租人法人变更，合同主体替换 | 发票抬头、欠费归属切换 |
| 面积变更 | 部分退租或扩租；组合/拆分租赁的业务规则固化 | 租控面积、账单重算 |
| 提前解约 | 违约金规则、免租追回、保证金抵扣顺序 | 退租退费 + 欠费结清 |
| 合同版本 | 每次变更生成合同版本号；附件与审批链完整 | 档案可查「生效中/历史」 |

**闭环联动**

```
合同到期预警 → 续签/退租分支 → 租控与账单同步 → 档案版本归档
```

**需求编号建议**：FR-CON-LC-001 ~ FR-CON-LC-006

---

### 3.5 退租清场与保证金闭环 【P0】

**现状缺口**

- 有「退租退费」页面，但缺少 **清场验收** 标准环节：房屋交接、设施清点、欠费确认、损坏赔偿。
- 保证金「收—占—扣—退」与租金欠费、维修赔偿的 **抵扣顺序** 未定义。

**最优方案**

**退租标准流程（建议固化为状态机）：**

```
退租申请 → 欠费与账单冻结 → 清场预约 → 现场验收（工作端）→ 验收确认
→ 费用结算（租金欠费 + 水电杂费 + 损坏赔偿 − 保证金抵扣）→ 保证金退/补
→ 合同终止 → 租控变空置 → 触发盘活/招租
```

| 单据 | 内容 |
|------|------|
| 清场验收单 | 交接时间、水电气读数、设施清单、照片、双方签字 |
| 退租结算单 | 应收/应退明细、抵扣顺序、最终应退金额 |
| 保证金流水 | 收取、占用、抵扣、退还每笔留痕 |

**抵扣顺序建议（可配置）**：赔偿 → 欠租 → 欠费杂费 → 退还余额

**闭环联动**

- 用户端可发起退租申请（可选 P1）
- 工作端清场验收、上传照片
- 财务在 PC 确认结算后退保证金
- 资产状态自动回写，空置资产进入招租池

**需求编号建议**：FR-VACATE-001 ~ FR-VACATE-005

---

### 3.6 催缴升级与法务协同 【P1】

**现状缺口**

- 履约催缴有欠费管理、催缴模板、短信，但缺少 **催缴等级升级** 与 **法务介入** 节点。
- 催缴效果（是否回款）与信用档案联动不足。

**最优方案**

| 催缴等级 | 动作 | 触发条件（示例） |
|----------|------|----------------|
| L1 提醒 | 短信/小程序消息 | 到期前 3 天 |
| L2 催告 | 催缴单生成 + 工作端张贴留痕 | 逾期 7 天 |
| L3 函告 | 律师函/正式催告书模板导出 | 逾期 30 天 |
| L4 法务 | 移交法务任务、诉讼登记 | 逾期 90 天或金额超阈值 |
| L5 清退 | 与提前解约、清场流程联动 | 协商失败 |

每条催缴记录：**催缴方式、时间、经办人、租户反馈、回款结果** 必填。

**闭环联动**

```
账单逾期 → 自动升级催缴 → 回款则关闭 → 未回款则升级 → 法务/清退 → 信用扣分
```

**需求编号建议**：FR-DUN-ESC-001 ~ FR-DUN-ESC-004

---

### 3.7 水电能耗与杂费计费 【P1】

**现状缺口**

- 「其他缴费」「水电表号」字段存在，但无 **抄表、分摊、周期出账** 完整链路。
- 退租结算时水电结清易扯皮。

**最优方案**

| 模块 | 功能 |
|------|------|
| 表计档案 | 资产/合同绑定水表、电表、气表编号与倍率 |
| 抄表记录 | 工作端/PC 录入读数；支持周期抄表任务 |
| 计费规则 | 单价、公摊比例、保底费用；按合同约定 |
| 杂费账单 | 自动生成杂费账单并入收费大厅「其他收费」 |
| 退租结清 | 清场验收读数与末次账单自动比对 |

**闭环联动**

```
表计建档 → 周期抄表任务 → 杂费账单 → 收费 → 退租末次抄表结清
```

**需求编号建议**：FR-UTIL-001 ~ FR-UTIL-005

### 3.8 经营性资产盘点与账实相符 【P0】

**现状缺口**

- 固定资产子系统有盘点，**经营性资产（房产/土地）** 缺少定期盘点与台账差异处理。
- 「资产盘清」目标在台账录入侧，现场核实机制弱。

**最优方案**

| 能力 | 说明 |
|------|------|
| 盘点计划 | 按公司/项目/楼栋发起；支持全盘、抽盘 |
| 移动端盘点 | 工作端扫码盘点：在租/空置/占用/异常占用 |
| 差异处理 | 盘盈、盘亏、信息不符 → 差异单 → 审批 → 台账调整 |
| 账实报告 | 盘点完成生成账实相符率报告，纳入经营考核 |

**闭环联动**

```
台账 → 盘点任务 → 现场核实 → 差异审批 → 台账/租控修正 → 看板更新
```

**需求编号建议**：FR-AST-AUDIT-001 ~ FR-AST-AUDIT-004

---

### 3.9 空置资产盘活管理 【P0】

**现状缺口**

- 租控与看板展示空置面积，但缺少 **空置原因分类、盘活方案、责任到人、时限跟踪**。
- 空置 91% 类指标只能看，难以管。

**最优方案**

| 字段/能力 | 说明 |
|-----------|------|
| 空置原因 | 新建空置、退租空置、维修空置、政策限制、产权瑕疵等 |
| 盘活方案 | 招租、改造、置换、委托经营、临时占用、处置 |
| 盘活任务 | 从预警或手工创建；责任人、目标日期、阶段（方案/挂牌/签约） |
| 空置时长 KPI | 空置天数自动累计；超 90/180 天高亮督办 |
| 盘活看板 | 按项目排名：空置面积、空置时长、盘活转化率 |

**闭环联动**

```
资产变空置 → 自动记因 + 创建盘活任务 → 招租/处置执行 → 签约后关闭任务 → 盘活率统计
```

**需求编号建议**：FR-VACANT-001 ~ FR-VACANT-004

---

### 3.10 业财一体与对账 【P1】

**现状缺口**

- 收费、发票、收款记录完备，但与 **财务总账/ERP、银行流水** 的对账闭环未定义。
- 国资监管常要求收入与凭证可追溯。

**最优方案**

| 能力 | 说明 |
|------|------|
| 收款对账 | 导入银行流水；按金额、日期、备注匹配收款记录 |
| 未达账项 | 在途、差异清单；人工勾稽 |
| 收入确认规则 | 权责发生制：按账单所属期确认收入（可配置） |
| 凭证接口 | 收款、退款、发票开具触发凭证模板（对接用友/金蝶等） |
| 月结 | 月末锁定账单；生成收费月报、收入月报 |

**闭环联动**

```
业务收款 → 收款记录 → 银行对账 → 收入确认 → 凭证推送 → 财务报表
```

**需求编号建议**：FR-FIN-001 ~ FR-FIN-005

---

### 3.11 巡检维保 SLA 与闭环质检 【P1】

**现状缺口**

- 报修—派工—完工有框架，缺少 **响应时效、完工时效、复检、满意度** 标准。
- 设计稿 PDF 提到「维修响应时效排名」，SRS 未固化规则。

**最优方案**

| 指标 | 规则示例 |
|------|----------|
| 响应 SLA | 接单后 2 小时内响应（可配置） |
| 完工 SLA | 一般维修 48 小时内完工 |
| 超时升级 | 超时自动预警并升级至上级 |
| 完工复检 | 租户确认或管理员抽检；可驳回返工 |
| 维保合同 | 维修公司合同、单价库、年度维保预算 |

**状态机补充**

```
待审核 → 待派工 → 已接单 → 维修中 → 待验收 → 已完成 / 已驳回
```

**闭环联动**

```
报修 → SLA 计时 → 超时预警 → 完工验收 → 满意度 → 维修公司 KPI 报表
```

**需求编号建议**：FR-MNT-SLA-001 ~ FR-MNT-SLA-004

---

### 3.12 合规备案与三重一大 【P1】

**现状缺口**

- 审批流程可配置，但未区分 **一般审批 vs 重大事项审批**（大额减免、低价出租、资产处置）。
- 公开招租、资产处置的 **备案材料包** 未标准化。

**最优方案**

| 事项 | 合规要求 |
|------|----------|
| 低价出租 | 低于评估底价需特批；附评估报告 |
| 大额减免 | 超过 N 元或 N% 需升级审批 |
| 资产处置 | 处置方案、评估、集体决策记录归档 |
| 备案导出 | 一键导出：审批链 + 附件 + 关键字段 PDF 包 |
| 三重一大标记 | 流程节点可标记「需上会」；系统留痕是否已上会 |

**需求编号建议**：FR-COMP-001 ~ FR-COMP-004

---

### 3.13 数据主数据与资产拆分合并 【P1】

**现状缺口**

- 支持组合租赁、拆分租赁操作，但 **资产物理拆分/合并** 对历史合同、权证、账单的影响规则未定义。

**最优方案**

| 操作 | 规则 |
|------|------|
| 资产拆分 | 原资产冻结；子资产继承权属；在租合同需先处理或整体挂接父合同 |
| 资产合并 | 多资产合并为一；空置资产方可合并 |
| 编码规则 | 统一编码：项目码 + 楼栋 + 楼层 + 单元；变更保留旧码映射 |
| 历史追溯 | 任意时点可查资产结构树 |

**需求编号建议**：FR-MDM-001 ~ FR-MDM-003

---

### 3.14 电子签约与合同存证 【P2】

**现状缺口**

- 合同模板、审批已有；**电子签章、租户线上签、存证** 未明确。

**最优方案**

- 对接电子签平台（e 签宝、法大大等）：租户用户端签署、企业盖章、签署状态回写合同。
- 合同 PDF 哈希存证；与档案中心永久关联。

**需求编号建议**：FR-ESIGN-001 ~ FR-ESIGN-003

---

### 3.15 无形资产与首页「四类资产」一致性 【P2】

**现状缺口**

- 首页应用中心含「无形资产」，SRS 经营性 + 固定资产详述，无形资产仅概念存在。

**最优方案（分期）**

- 二期建设 **无形资产台账**：经营权、特许权、股权类资产；评估、摊销、到期预警。
- 一期在首页标注「敬请期待」或隐藏入口，避免用户预期落差。

## 4. 关键业务规则汇总（建议写入 SRS 附录）

### 4.1 租控状态机

| 状态 | 含义 | 可转入 |
|------|------|--------|
| 空置 | 可招租 | 招租中、自用、占用、处置中 |
| 招租中 | 已挂牌 | 空置、在租（签约后） |
| 在租 | 有效合同 | 退租中、部分出租 |
| 部分出租 | 组合/拆分场景 | 在租、空置 |
| 自用 | 内部使用 | 空置 |
| 占用 | 临时占用 | 空置、在租 |
| 退租中 | 清场流程中 | 空置、在租（异常回滚） |
| 处置中 | 处置审批中 | 已退出 |
| 已退出 | 档案封存 | — |

**规则**：租控状态仅由 **合同、自用单、占用单、退租单、处置单** 驱动变更，禁止手工直接改状态（超管除外且须留痕）。

### 4.2 账单与收款状态机

| 账单状态 | 说明 |
|----------|------|
| 待出账 | 计划内未到期 |
| 待缴 | 已出账未支付 |
| 部分缴 | 部分支付 |
| 已缴 | 全额支付 |
| 已减免 | 审批减免核销 |
| 已作废 | 合同变更/退租冲销 |

**规则**：已缴账单不可删除，仅可冲正并留痕。

### 4.3 保证金处理顺序（默认）

1. 抵扣损坏赔偿  
2. 抵扣租金及杂费欠费  
3. 退还租户（原路或线下，需审批）
