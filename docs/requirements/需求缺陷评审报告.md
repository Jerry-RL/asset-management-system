## 1. 评审结论

现有 SRS 骨架质量高：主链路（台账→招租→签约→收费→催缴→退租→处置）完整、三端分工清晰、十三条闭环 + 八套状态机 + 数据安全四级分级均已建立，属已完成两轮闭环评审的成熟基线。

但从「**真的能为客户创造价值并顺利上线**」角度，仍存在三类缺陷：

1. **闭环在关键节点上是断的** —— 有状态机外壳、缺核心算法（收费三大算法、组合拆分计费）。
2. **上线前置条件缺失** —— 缺期初数据迁移与建账需求，系统无法从旧世界切换到新世界。
3. **价值指标与验收脱节、智能化投入错配** —— 业务 KPI 未纳入验收，Agent 投入回报弱且排期过早。

缺陷分级统计：**P0 级 5 项、P1 级 9 项、P2 级 6 项，合计 20 项**。其中 P0 的第 1–4 项（期初迁移、不足月折算、滞纳金、核销分配）已在本报告 §3 展开为**可直接并入 SRS 的需求补充条目**。

### 2.1 P0 级（会导致闭环断裂 / 无法上线兑现价值）

| # | 缺陷 | 问题本质 | 业务影响 | 补充章节 |
|---|------|----------|----------|----------|
| 1 | 期初数据/历史数据迁移需求缺失 | 商业论证与开发计划提到「数据迁移」，但 SRS 无「期初在租合同、历史欠费余额、保证金/预收余额、在途账单」的导入与建账需求 | 系统上线的前置条件缺失，无法「一本账」 | §3.2 FR-MIG-* |
| 2 | 首期/末期租金「不足月折算」规则缺失 | 定价引擎有递增、免租、阶梯，但无「起租日非月初 / 退租日非月末时按日折算」规则 | 首尾两期应收算错，破坏「应收/实收/欠费」准确性 | §3.3.1 FR-PRICE-007~008 |
| 3 | 滞纳金/违约金计算规则缺失 | 催缴有 L1–L5 升级，但滞纳金比例、起算日、封顶、是否计入应收未定义 | 欠费「应收总额」口径不清，法务/清退无金额依据 | §3.3.2 FR-DUN-LATE-* |
| 4 | 一笔收款核销多张账单的分配规则缺失 | FR-REF 定义冲正，但「一笔钱如何匹配历史多张欠费单」（FIFO/指定/按比例）未定义 | 「部分缴」状态无法正确流转，催缴/预收抵扣全依赖它 | §3.3.3 FR-PAY-* |
| 5 | 组合/拆分租赁计费规则被「逃逸」 | FR-OPS-002 出现组合/拆分租赁，但 SRS 写「留 DSD 细化算法」 | 一资产多租户、面积拆分的计量是硬骨头，需求不定义必返工 | §3.3.4 |

> **关键判断**：缺陷 2/3/4 是「**收费闭环的三大核心算法**」——不足月折算、滞纳金、核销分配。它们决定「应收是否算得对、实收是否核得清、欠费是否追得准」，正是 ROI 报告中「收缴率提升 3–8%」这一**最大价值来源**的数学基础。当前 SRS 只有状态机、没有算法，属「有闭环外壳、缺闭环内核」。

### 3.2 期初数据迁移与建账 **[P0]**

**需求编号**：FR-MIG-001 ~ FR-MIG-008

**定位**：系统切换（上线）的前置条件。将旧台账/旧系统/线下 Excel 中的在租业务与资金余额「平移」进新系统，保证上线首日「账实相符、一本账」可对外交付。缺本组需求则系统无法上线。

**总原则**：

1. 迁移与建账须有**统一基准日（Cutover Date）**，所有期初余额以该日为准冻结快照。
2. 迁移完成后须做**试算平衡**：期初在租合同应收合计 = 期初欠费合计 + 期初实收（历史）合计，不平不进试运行。
3. 所有期初数据标记来源 `source=迁移`，与上线后新增数据可区分、可追溯，但不可被业务人员手工修改（仅超管经审批可修正，留痕）。

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-MIG-001 | 期初资产台账导入 | 导入项目、房产/土地资产基础档案、权证、抵押、价值信息；支持 Excel 模板 + 校验（必填、编码唯一、面积/金额非负）；校验失败逐条报错可回退 |
| FR-MIG-002 | 期初在租合同导入 | 导入「生效中」合同：租户、资产、租期（起止日）、租金类型与金额、缴费周期、当前缴费截止日、缴费状态；用于初始化租控=在租 |
| FR-MIG-003 | 期初账单与欠费余额 | 导入每个在租合同的历史应收、实收、**欠费余额**及账龄；生成期初欠费台账（与 FR-DUN-* 联动，用于催缴起算） |
| FR-MIG-004 | 期初保证金余额 | 按合同导入保证金实收余额、占用状态（是否已用于抵扣）；区分「已收未退」「应退未退」 |
| FR-MIG-005 | 期初预收/预交余额 | 导入预收租金余额台账（按合同/租户），与 FR-PREPAY-* 联动；迁移后新账单可自动抵扣 |
| FR-MIG-006 | 期初租控状态初始化 | 按 FR-MIG-002~005 结果自动初始化租控：在租/占用/自用/处置中/退租中；无有效合同且非占用/自用的 → 空置；空置须填「空置原因」（FR-VACANT-001） |
| FR-MIG-007 | 期初催缴状态与信用档案 | 对期初欠费租户初始化催缴等级（L1–L5）与历史催缴记录；按 FR-TENANT-CREDIT-* 初始化信用分 |
| FR-MIG-008 | 迁移校验与试运行对账 | 提供迁移对账报告：期初合同数/面积/金额与旧系统核对；「期初应收=期初欠费+期初实收」试算平衡；差异人工勾稽；通过后锁定基准日进入试运行 |

**闭环**：旧系统/线下台账 → 按基准日导出 → 模板校验导入 → 试算平衡 → 锁定进入试运行 → 上线后增量记账。

**验收要点**：

- 任选一在租资产，其「合同金额、欠费余额、保证金余额」与新系统期初台账一致；
- 期初欠费租户上线即出现在催缴队列，且等级正确；
- 试算平衡报告可导出且无未勾稽差异。

### 3.3 收费核心算法

#### 3.3.1 首末月不足月折算 **[P0]**

**需求编号**：FR-PRICE-007 ~ FR-PRICE-008

**定位**：补齐「缴费计划生成」（FR-PRICE-005）的计量规则。起租日非月初、退租/解约日非月末时，首末两个非整月期间须按日折算，否则首尾两期应收金额错误，直接污染收缴率。

| 编号 | 规则 | 说明 |
|------|------|------|
| FR-PRICE-007 | 首末月折算规则 | 首期/末期不足整月时，应收 = 月租金 ×（实际租用天数 ÷ 折算分母）。折算分母二选一，由合同或系统参数统一配置：**A. 按当月自然日**（如 17/31）；**B. 按固定 30 天**（如 17/30）。同一合同全程采用同一口径 |
| FR-PRICE-008 | 精度、舍入与尾差 | 每期金额保留 2 位小数（四舍五入）；因舍入产生的累计尾差在**最后一期账单**一次性调整（多退少补），保证「全周期应收合计 = 合同总额」精确相等；退租提前解约时按实算天数重算末期并作废原末期计划 |

**业务规则**：

- 免租期（FR-PRICE-004）若落在首/末非整月，免租天数与折算天数重叠时，先扣免租再折算，口径须可配置并在合同上留痕。
- 递增/阶梯（FR-PRICE-003）的档位切换日若落在月内，该月按档位分段计后合并，不允许整月按单一档位近似。

**闭环**：合同起止日 → 规则引擎判定非整月 → 按日折算生成首末期计划 → 尾差并入末期 → 应收与合同总额一致。

**验收要点**：构造「起租 2026-03-15、月租 10,000、按当月自然日」案例，首期应收 = 10,000 × 17/31 = 5,483.87 元；全周期应收合计精确等于合同总额。

#### 3.3.2 滞纳金/违约金计算 **[P0]**

**需求编号**：FR-DUN-LATE-001 ~ FR-DUN-LATE-004

**定位**：为「履约催缴升级」（FR-DUN-ESC-*）与「退租结算」（FR-VACATE-*）提供**可入账、可举证的欠费金额依据**。滞纳金是催缴与法务清退的金额基础。

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-DUN-LATE-001 | 滞纳金规则配置 | 可配置：**日利率/月利率**（如日 0.05%）、**起算日**（账单到期日次日，或宽限 N 天后起算）、**封顶**（如不超过本金 50% 或固定上限）、**是否计入应收总额**；按公司/合同类型可设不同模板 |
| FR-DUN-LATE-002 | 自动计息 | 每日定时任务对「未结清账单」按滞纳金规则滚动计息，生成滞纳金明细（金额、期间、利率快照）；计息金额随催缴等级联动展示于催缴单/律师函 |
| FR-DUN-LATE-003 | 滞纳金减免与豁免 | 与 FR-ADJ-* 减免流程联动：可对滞纳金单独申请减免或豁免，超阈值走升级审批；减免后计息基数同步调整并留痕 |
| FR-DUN-LATE-004 | 入账与法务依据 | 滞纳金计入欠费台账「应收」；退租结算（FR-VACATE-002）将「本金欠费 + 滞纳金」一并纳入抵扣顺序；律师函/催告书模板自动带出本金、滞纳金、起算日与已计天数 |

**业务规则**：

- 滞纳金**只对本金欠费计息**，不「利滚利」（是否复利须明确，默认不复利）。
- 计息停止条件：全额结清、减免核销、合同终止/退租结算完成、账单作废。
- 利率调整仅对**调整日后**的天数生效（利率快照留痕，见缺陷 #12 配置版本）。

**闭环**：账单逾期 → 滞纳金规则计息 → 计入应收欠费 → 催缴单/律师函带出金额 → 退租/清退结算抵扣。

**验收要点**：欠费 10,000 元、日利率 0.05%、逾期 30 天 → 滞纳金 = 150 元；减免 50% 后计息基数正确回落；退租结算单金额含本金+滞纳金。

#### 3.3.3 收款核销与分配 **[P0]**

**需求编号**：FR-PAY-001 ~ FR-PAY-005

**定位**：补齐「收费大厅 / 收款记录」的**核销算法**。一笔收款如何匹配到多张历史账单，决定「已缴/部分缴/待缴」账单状态机（§4.24.2）能否正确流转，也是退款冲正（FR-REF-*）与预收抵扣（FR-PREPAY-*）的基础。

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-PAY-001 | 核销策略配置 | 可配置核销顺序，默认 **FIFO（先欠先核）**：按账单到期日先后依次核销；可选「指定账单核销」「按比例核销」；同一合同全程使用一致策略 |
| FR-PAY-002 | 收款与账单核销 | 一笔收款可拆分核销多张账单；支持全额核销与**部分核销**；部分核销后账单状态=部分缴，记录「已核金额/未核金额」 |
| FR-PAY-003 | 核销优先级与冲正联动 | 同一账单存在「本金 + 滞纳金」时，可配置核销顺序（默认先滞纳金后本金，或先本金后滞纳金）；冲正（FR-REF-003）时按原核销记录**逆序回退**账单状态（已缴→部分缴/待缴），保证账账一致 |
| FR-PAY-004 | 预收抵扣规则 | 预收余额（FR-PREPAY-001）在账单出账后按「到期先后」自动抵扣；抵扣生成核销流水，与收款核销共用同一核销台账 |
| FR-PAY-005 | 核销流水与对账 | 每笔核销生成不可变流水（收款单号、账单号、核销金额、时间、操作人）；作为收款记录、业财对账（FR-FIN-001）与发票核销（FR-INV-LC-002）的单一事实来源 |

**业务规则**：

- 收款金额不得超过「可核销总额」（= 未核销本金 + 未核销滞纳金）；超额部分转预收或原路退回，需配置默认动作。
- 已全额核销的账单不可再次核销；核销流水不可删改，仅可经冲正反向对冲。
- 一收款冲正后，关联的发票若已开票，须联动红冲（FR-INV-LC-003）。

**闭环**：收款入账 → 按策略匹配账单 → 生成核销流水 → 账单状态流转 → 退款/冲正逆序回退 → 对账/发票联动。

**验收要点**：租户欠 B1=8,000（先到期）、B2=6,000（后到期），收款 10,000 → FIFO 下 B1 全额核销、B2 部分核销（欠 4,000）；冲正后两账单状态按逆序正确回退。

#### 3.3.4 组合/拆分租赁计费规则 **[P0]**

**需求编号**：FR-OPS-006（计费口径）、FR-MDM-004（拆分映射）

**定位**：将 SRS 中「留 DSD 细化」的组合/拆分租赁计费规则**上移到需求层**，明确业务口径，算法实现细节再下沉。

| 编号 | 规则 | 说明 |
|------|------|------|
| FR-OPS-006 | 组合/拆分计费口径 | 一资产多租户（拆分租赁）：按**面积占比或独立计量**计租，账单按租户独立生成、独立核销；多资产打包（组合租赁）：可整包计租或按资产分摊，账单须能追溯到单资产（用于资产维度收缴率统计） |
| FR-MDM-004 | 拆分后的账单与合同映射 | 资产物理拆分（FR-MDM-001）后，原在租合同的账单须按拆分结果**拆分或整体挂接**，明确「父合同拆分账单」或「原合同终止+子合同新签」二选一规则，禁止出现无归属账单 |

**业务规则**：

- 组合租赁的每个子资产面积之和 ≤ 资产总面积，超出须校验阻断。
- 拆分/组合产生的面积变更须触发租控面积与账单重算（FR-CON-LC-004 联动），重算历史留痕可追溯。

**验收要点**：一资产拆分为 A/B 两租户，各自账单金额按面积占比正确、可独立核销；组合租赁账单可下钻到单资产的收缴率。

## 4. 价值导向建议（给客户的行动项）

1. **先补「三个算法 + 一个前置」再动工**：不足月折算、滞纳金、核销分配（§3.3）加上期初数据迁移（§3.2），是「收缴率提升」这一**核心价值主张**能否兑现的数学与落地基础，优先级应高于任何 P1/P2 功能。

2. **把业务 KPI 写进验收**：建议在 SRS §10 增加「效益验收」一节，上线后以「收缴率、空置率、线上缴费占比、退租纠纷件数」作为试运行 3 个月的量化验收项，否则「为客户创造价值」只停留在定性描述。

3. **砍/后置智能 Agent，聚焦现金流闭环**：在 250–400 万的建设盘子里，Agent（W6/W7 + 私有化 LLM 年 7–23 万）是 ROI 最弱、风险最高的一块。建议降级为「模板 + 固定 Tool 的只读报告」（NFR-AI-008 已有降级方案），把人力与预算转投催缴升级、业财对账、数据迁移三块高价值闭环。

4. **组合/拆分租赁不要留到 DSD**：这是收费计量风险最高的需求逃逸，已在本报告 §3.3.4 给出计费口径与账单拆分原则，建议在 SRS 阶段采纳。
