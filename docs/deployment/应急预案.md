# 应急预案

| 版本 | V1.1 |
|------|------|
| 日期 | 2026-08-26 |
| 适用范围 | 资产经营管理系统生产环境 |

---

## 1. 目的

规范 **故障响应、灾难恢复、安全事件** 处理流程，最小化业务中断与数据损失。

## 2. 应急组织

| 角色 | 职责 | 联系方式（填写） |
|------|------|------------------|
| 应急指挥 | 项目经理 / 业主指定 | |
| 技术负责人 | 故障诊断、修复决策 | |
| 开发值班 | 代码修复、热补丁 | |
| 运维值班 | 基础设施、重启、回滚 | |
| DBA | 数据库恢复 | |
| 业务联系人 | 对外公告、用户沟通 | |

**值班轮换表**：由运维维护，每月更新。

## 3. 事件分级

| 级别 | 定义 | 响应时间 | 恢复目标 |
|------|------|----------|----------|
| P0 | 系统不可用、数据丢失、支付异常 | 15 分钟响应 | 4 小时内恢复核心功能 |
| P1 | 核心功能受损（无法签约/收费） | 30 分钟 | 8 小时内 |
| P2 | 非核心功能异常、性能下降 | 2 小时 | 24 小时内 |
| P3 | 轻微问题、有 workaround | 下一工作日 | 按计划修复 |

## 4. 应急流程

```
发现 → 通报指挥 → 定级 → 组建小组 → 止损 → 根因分析 → 修复 → 验证 → 复盘报告
```

通报渠道：电话 + 即时通讯群 + 工单系统。

## 5. 典型场景与处置

### 5.1 API 全站不可用

| 步骤 | 动作 |
|------|------|
| 1 | 检查 Nginx、API 进程、健康检查 |
| 2 | 查看最近发布；必要时 [部署手册](./部署手册.md) 回滚应用 |
| 3 | 检查 PG/Redis 连通 |
| 4 | 恢复后全链路冒烟 |

### 5.2 数据库故障

| 步骤 | 动作 |
|------|------|
| 1 | 确认主库状态；切换只读维护页（若已配置） |
| 2 | 联系 DBA：主从切换或从备份恢复 |
| 3 | 评估数据丢失窗口（RPO）；按 §6 恢复 |
| 4 | 恢复后校验账单、合同一致性 |

### 5.3 支付成功未入账

| 步骤 | 动作 |
|------|------|
| 1 | 查微信商户平台订单状态 |
| 2 | 查回调日志与 `traceId` |
| 3 | 验签失败：修配置后手动补单（财务审批） |
| 4 | 通知受影响租户 |

### 5.4 安全事件（疑似入侵、数据泄露）

| 步骤 | 动作 |
|------|------|
| 1 | **15 分钟内止损**：隔离受影响实例/账号；暂停可疑导出与 API Key |
| 2 | 轮换 JWT、OSS、DB、`DATA_ENCRYPTION_KEY`（按影响范围） |
| 3 | 保全 `operation_log`、`security_event`、`export_audit`、网关日志 |
| 4 | 通知信息安全负责人；评估个保法/数据安全法报告义务 |
| 5 | 72h 内提交复盘；更新 [数据安全设计说明书](../design/数据安全设计说明书.md) 若策略变更 |

**数据类 P0 附加检查**：

- 是否发生 L3/L4 批量导出或越权查询
- Agent/LLM 是否外泄未脱敏 Prompt
- 备份/快照是否被非授权访问
- 测试环境是否误用生产明文数据

### 5.5 性能崩溃（200+ 用户卡顿）

| 步骤 | 动作 |
|------|------|
| 1 | 查 CPU/慢查询/连接池 |
| 2 | 临时扩容 API 实例 |
| 3 | 启用/加大缓存；限制导出等大查询 |
| 4 | 按 [性能测试报告](../testing/性能测试报告.md) 优化 |

## 6. 备份与恢复

| 对象 | RPO | RTO | 恢复步骤 |
|------|-----|-----|----------|
| PostgreSQL | ≤ 24h（日备）+ WAL | ≤ 4h | `pg_restore` 至新实例，切换连接串；**备份须加密** |
| Redis | 日快照 | ≤ 1h | 重启 + RDB 恢复（可接受缓存丢失） |
| OSS 附件 | 实时复制 | ≤ 4h | 切换副本桶 |
| 配置密钥 | 版本库 + 密钥管理 | ≤ 1h | 重新注入环境变量 |

**恢复演练**：每季度至少 1 次，记录于运维月报。

## 7. 降级策略

| 功能 | 降级方式 |
|------|----------|
| 电子发票 | 暂停线上开票，手工开票 |
| 电子签 | 线下纸质合同扫描上传 |
| 经营看板 | 只读缓存数据，暂停实时重算 |
| 用户端支付 | 引导线下缴费登记 |

## 8. 对外公告模板

> 【系统维护通知】资产经营管理系统因 {原因} 于 {时间} 出现 {影响}，我们正在紧急处理，预计 {时间} 恢复。如有紧急缴费请联系 {电话}。给您带来不便敬请谅解。

## 9. 事后复盘

P0/P1 事件 **72 小时内** 提交复盘报告：

- 时间线
- 根因（技术/流程/人为）
- 改进项与责任人
- 是否更新本预案或 ADR
