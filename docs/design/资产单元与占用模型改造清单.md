### 2.3 六处绕过状态机的直写

改造前状态机不是唯一入口，本 ADR 的核心收益（单一写入口）在清理前不成立。

> **进度（2026-09-11）**：已清 3 处 —— 触点 14（`ImportExportService`）、触点 16（`MigrationService`）、触点 17（`AssetService`）；待清 3 处 —— 触点 1（`LeaseControlService` 及 8 处调用）、触点 15（`AssetStructureService` 拆分/合并）、触点 18（`DemoDataSeeder`，需先决策）。
>
> **进度（2026-09-14，依 [ADR-0021](../adr/0021-asset-split-merge-rules.md) 复核）**：触点 15 **未开工，且经代码核对确认 4 项 P0 缺陷仍然存在**（D-01 子资产无单元 / D-02 合并后影子可租 / D-03 编码违规 / D-04 只看派生列）。另新增 **D-05：合同链路未接入单元/占用**（`ContractService:207` 仍写资产级状态，`contract.asset_unit_id` 在 Java 侧从未写入）——它是触点 8 的实际状态，也是"拆分合并无法支撑租赁业务"的**首要阻塞**。触点 15 升级为**整段重做**，子任务拆到触点 33~39（§2.4），缺陷与触点的对应关系见 §2.6。
>
> **新增缺口（本轮发现，非清单原有）**：
> - **驳回链路缺失**：`OccupationService`/`SelfUseService` 原先只启动审批、不监听 `ApprovalCompleted`，且无 `withdraw` 端点 → 单据永久停在 `approving`，接入预留态后**预留行会泄漏并永久锁死单元**。本轮已补 `withdraw` 端点 + `onApprovalCompleted` 监听；其余域（如 `FeeReliefService`/`RentAdjustService` 已有监听）需逐一核对。
> - `SelfUseController` 原先**没有 `/submit` 端点**（自用申请提交不可达），本轮已补。

## 3. 验收 SQL

```sql
-- INV-1：单元面积不得超过资产面积（期望仅 area_missing / no_unit 可解释）
SELECT * FROM v_asset_unit_budget WHERE check_result <> 'ok';

-- A1 不变量：占用面积恒等于单元面积
SELECT count(*) FROM asset_occupancy o JOIN asset_unit u ON u.id = o.asset_unit_id
 WHERE u.area <> o.area;

-- INV-2：每个资产至少一个有效单元
SELECT * FROM v_asset_without_unit;

-- 非终态合同必须已挂单元
SELECT * FROM v_contract_without_unit;

-- 派生一致性（切换读路径前必须为空）
SELECT * FROM v_asset_lease_status_reconcile;

-- 存量面积差异（仅供人工决定是否拆单元，不阻塞；视图由 V41 §2.4 创建）
SELECT * FROM v_legacy_area_mismatch;

-- 预留态（ADR-0020 决策 E）：reserving 应只存在于审批中的单据
SELECT o.subject_type, o.subject_id, count(*) AS reserved_units
  FROM asset_occupancy o
 WHERE o.biz_status = 'reserving' AND o.date_to IS NULL
 GROUP BY o.subject_type, o.subject_id;

-- 派生租控状态不得被 reserving 污染（评审 P0-6）
SELECT * FROM v_asset_lease_status_derived d
 WHERE EXISTS (SELECT 1 FROM asset_occupancy o
                WHERE o.asset_id = d.asset_id
                  AND o.biz_status = 'reserving'
                  AND CURRENT_DATE <@ daterange(o.date_from, o.date_to, '[)'))
   AND d.derived_status <> 'vacant';

-- 组合租赁占用收口完整性（评审 P0-5）：已终止合同不应残留未收口占用
SELECT c.id, c.contract_no, count(*) AS open_occupancies
  FROM contract c
  JOIN asset_occupancy o ON o.subject_type = 'contract' AND o.subject_id = c.id
 WHERE c.status = 'terminated' AND o.date_to IS NULL
 GROUP BY c.id, c.contract_no;

-- ⑩ 结构树中的活动子资产必须有有效单元（INV-14 / ADR-0021 D-01）
SELECT c.id AS child_asset_id, c.asset_no, c.structure_status
  FROM asset c
 WHERE c.deleted_at IS NULL
   AND c.parent_asset_id IS NOT NULL
   AND c.structure_status = 'active'
   AND NOT EXISTS (SELECT 1 FROM asset_unit u
                    WHERE u.asset_id = c.id AND u.deleted_at IS NULL);

-- ⑪ 已冻结/已合并退出的资产不得残留未收口占用（INV-15 / D-04）
--    例外：attach_parent 策略下父资产仍持在租合同，须在本结果中显式列出并人工确认
SELECT a.id, a.asset_no, a.structure_status, o.subject_type, o.subject_id, o.date_from
  FROM asset a
  JOIN asset_occupancy o ON o.asset_id = a.id
 WHERE a.structure_status IN ('frozen', 'merged_out')
   AND o.date_to IS NULL;

-- ⑫ 价值守恒（INV-16 / D-06）：冻结父资产原值应等于其活动子资产合计
SELECT p.id AS parent_id, p.asset_no, p.original_value AS parent_value,
       COALESCE(SUM(c.original_value), 0) AS children_value
  FROM asset p
  JOIN asset c ON c.parent_asset_id = p.id
              AND c.structure_status = 'active'
              AND c.deleted_at IS NULL
 WHERE p.structure_status = 'frozen' AND p.deleted_at IS NULL
 GROUP BY p.id, p.asset_no, p.original_value
HAVING ABS(p.original_value - SUM(c.original_value)) > 0.005;

-- ⑬ 冻结/已合并退出的资产不得被合同或招租引用（INV-17 / D-02）
SELECT 'contract' AS ref_type, c.id AS ref_id, c.contract_no AS ref_code,
       a.asset_no, a.structure_status
  FROM contract c JOIN asset a ON a.id = c.asset_id
 WHERE a.structure_status IN ('frozen', 'merged_out')
   AND c.status NOT IN ('voided', 'terminated', 'expired')
UNION ALL
SELECT 'listing', l.id, CAST(l.id AS text), a.asset_no, a.structure_status
  FROM lease_listing l JOIN asset a ON a.id = l.asset_id
 WHERE a.structure_status IN ('frozen', 'merged_out')
   AND l.status = 'active';

-- ⑭ 合同必须挂单元（D-05）：非终态合同未写 asset_unit_id 即链路未接入
SELECT c.id, c.contract_no, c.status, c.asset_id
  FROM contract c
 WHERE c.status NOT IN ('voided', 'terminated', 'expired')
   AND c.asset_unit_id IS NULL;

-- ⑮ INV-19 占用收口对称性（ADR-0021 决策 I / D-22~D-26）：
--    来源单据已进入终态，却仍存在未收口（date_to IS NULL）的占用行。
--    期望恒为空；非空即意味着单元被永久锁死、续签/转租将失败，或合同已到期仍显示在租。
--    ⚠️ 终态集合必须包含 'expired'（D-26）；漏掉它会让「到期未收口」长期逃过检查。
--    说明：非合同类单据（occupation_order / self_use_order / disposal_order）的
--    「终态」取值需按各自状态机补全后再纳入，此处不臆造字面量。
SELECT 'contract' AS subject_type, c.id AS subject_id, c.contract_no AS subject_code,
       c.status, count(*) AS open_occupancies
  FROM contract c
  JOIN asset_occupancy o
    ON o.subject_type = 'contract' AND o.subject_id = c.id AND o.date_to IS NULL
 WHERE c.status IN ('terminated', 'voided', 'expired')
 GROUP BY c.id, c.contract_no, c.status;

-- ⑯ INV-19 续签/转租重叠前置检查（D-25）：
--    同一资产上存在多份非终态合同（续签未收口旧合同、转租未收口原合同）时告警，
--    因为「接占用」后它们的占用区间将必然重叠并被 EXCLUDE 拒绝。
SELECT a.id AS asset_id, a.asset_no, count(*) AS live_contracts,
       string_agg(c.contract_no || '(' || c.status || ')', ', ') AS contracts
  FROM contract c
  JOIN asset a ON a.id = c.asset_id
 WHERE c.status IN ('active', 'expiring', 'renewable', 'approving')
 GROUP BY a.id, a.asset_no
HAVING count(*) > 1;
```

## 4. 发布顺序与注意事项

**每步可独立上线：**

-1. **切片 0：只读比对接线（零风险，应最先做）**：把 `LeaseStatusDeriver.refreshReconciled`（`:112`）接到周期任务，**只统计告警、不改数据**。理由：该方法与 `v_asset_lease_status_reconcile` 查询**已实现但全库无调用方**（`platform/job` 下也没有），因此当前「派生列与占用集合不一致」既不为零、也不可见。这一步不依赖任何待定决策、不动写入路径，却能把整个问题的规模从"不可见"变成"一个数字"——**后续所有排期讨论都应以它为输入**（触点 43）。
0. **P0′ 语义修补（ADR-0020 决策 E/F）**：`V42__occupancy_reservation.sql` **已交付**（派生视图排除 `reserving` + `reserved_area` + `v_occupancy_reserving_orphan`），配套 `OccupancyBizStatus.RESERVING`、`findOpenBySubject` 的 `LIMIT 1` 已删除。**仍未完成的是业务链路接入**：合同/占用/自用/处置的「提交审批 → `reserve`、通过 → `activateBySubject`、驳回 → `cancelReservation`」属 §2.2 双写期改造（触点 28）。`domain_event_outbox`（决策 F）与 `contract_line`（决策 C）见后续 `V43+`。
   ⚠️ 提醒：只上预留态不上视图过滤，会造成「审批中即显示在租」的回归（评审 P0-6）；只改视图不改释放逻辑，组合租赁占用仍永久不收口（评审 P0-5）——两者本次已同批交付。
1. **P0 扩展（已完成）**：`V39~V41` + 新服务。应用写入路径**不切换**，跑 1~2 个迭代观察 §3 的差异清单。
2. **P1 双写**：§2.2 / §2.3 改造（**优先触点 8：合同链路接入单元/占用**），同时保留旧 `transition` 调用；一致性作业每日比对。⚠️ **触点 8 的收口路径（触点 44~47）必须同批交付，触点 48 是其前置设计**——只写不收口会造成单元永久锁死或续签失效（决策 I / D-22~D-25）。**用双写而不是替换**：保留 `transition(LEASED)` 的同时新增 `occupy`，两者在"占用行存在"时结论一致，因此双写期不会产生分歧，也保留了回退路径。资产层拆合收窄（触点 15 的字段补全 / 价值分摊 / 切分线对齐单元 / 结构状态门禁）与单元层拆合（触点 33~47）随本阶段推进，顺序见上方注意事项。
3. **P2 切读**：报表 / 看板 / 统计切到 `v_asset_lease_status_derived`；`pageAssets` 切按单元统计。
4. **P3 收敛**：`V43+` 加 `CHECK (status IN ('voided','terminated','expired') OR asset_unit_id IS NOT NULL)`、删除 `asset.partial_lease_status`、`asset.lease_area` 改为派生列。

**注意事项：**

- **拆合的依赖顺序（[ADR-0021](../adr/0021-asset-split-merge-rules.md)）**：触点 **43（只读比对接线）→ 8（合同链路接入单元/占用）→ 15 / 33~47（拆合）**。
  - 触点 43 排最前：`refreshReconciled` 已实现但**未接线**，漂移既不为零也不可见；先上**只读统计 + 告警**（不改数据、零风险），把不可见变成可观测数字。
  - 触点 8 先于拆合：先做拆合则单元**对合同不可见**——合同仍按资产级状态写，拆分反而放大 D-01（子资产无单元）与 D-02（影子可租）的暴露面。
  - 正确顺序：只读比对接线 → 合同接单元与占用 → 资产层拆合收窄（字段补全/价值分摊/切分线对齐单元/结构状态门禁）→ 单元层拆合接口与前端入口 → 最后前端入口。
- **触点 8 的收口不可分期（决策 I / D-22~D-26）**：触点 **44~47、50 必须与触点 8 同批交付**，触点 **48（区间语义定义）是 8 的前置设计**，触点 **49（CR checklist）同批固化**。理由：合同占用 `dateTo = null` 为开区间，只写不收口会因 `EXCLUDE` 造成**单元永久锁死**，或使**续签/转租直接失败**——**比不改更糟**。切勿"先加 `occupy`、收口下期再说"。
  - **为什么是五处而不是四处**：`v_unit_lease_status`（`V42:29-73`）**不读 `contract` 表**，因此「合同状态」与「派生租控状态」之间唯一的耦合就是占用行 → **合同生命周期的每一个终止态都必须显式收口**，包括**到期**（触点 50）。
- **完整落地方案见 [资产拆合落地实施方案](./资产拆合落地实施方案.md)**：含批次划分（B0~B6）、每批验收信号与回退方式、灰度开关、数据回填顺序、测试方案与待决决策截止时间。
- **决策 E 未签字前不得硬编码门禁**：`partial_lease_status` 的去留（显式开关 vs 由 `unit_count > 1` 派生）未定前，单元拆分规则 S1 不得写成"该字段 = `support`"，否则与设计 §12.3"删除该字段"的既定决策冲突。
- **`ApplicationRunner` 顺序陷阱**：`DemoDataSeeder` / `DemoDataConsistencyEnricher` / `DemoProjectImageSeeder` 在 Flyway **之后**运行，其创建的资产不经过 V39 回填。必须调 `AssetUnitService.ensureUnitForAsset`，否则 `v_asset_without_unit` 会持续非空。
- **`contract.asset_id` 不可删**：全库 60+ 处引用，且 RBAC 数据范围、看板、报表均依赖。保留为冗余投影 + 一致性校验，不做全链路 JOIN 改造。
- **`lease_bundle_item` 与 `asset_unit` 的分工**：前者是 bundle 的**分配明细**（保 `area_ratio` / `rent_amount`），后者是资产的**可租标的身**身份（保 `area` / `unit_status`），两者靠 `asset_unit_id` 关联，不互为真源。
- **审批中需预留面积**：`approving` 状态的合同必须计入 `LeaseAreaGroups.AREA_HOLDING`，否则并发签约会超租；撤销时释放。
- **回填优先级是确定性的**：`contract > self_use > occupation > disposal`，重叠行被守卫跳过（实测 A10 冲突只保留 `self_use`）。被跳过的数据需人工核对，不由迁移自动裁决。
- **`area = 0` 表示面积待补**：占位单元不参与面积统计，由 `v_asset_unit_budget.area_missing` 报出。

## 5. 实测结论

在 `postgres:16-alpine` 上用合成数据跑完整迁移链（V1→V41 + 14 个覆盖各分支的资产样例）：

| 校验项 | 期望 | 实测 |
|---|---|---|
| `contract.asset_unit_id` 回填覆盖率 | 100% | `contracts_without_unit = 0` |
| 每个资产至少一个单元 | 100% | `assets_without_unit = 0`，14 资产 → 17 单元 |
| 占用回填条数 | 11 | 11（contract 6 active + 1 vacating、self_use 2、occupation 1、disposal 1） |
| A1 不变量（占用面积 == 单元面积） | 0 违例 | `a1_violations = 0 / 11` |
| 派生态识别「部分出租」 | 仅 T-A3 | 仅 `T-A3: leased → partial_leased, ratio 30.00` |
| `EXCLUDE` 拒绝重叠占用 | 违反 `ex_occupancy_unit_no_overlap` | 实测报错 `conflicting key value violates exclusion constraint` |
| `EXCLUDE` 允许不重叠区间 | 成功 | `INSERT 0 1` |
| 非排他占用（`exclusive=false`）允许重叠 | 成功 | `INSERT 0 1` |
| 冲突数据裁决 | 只保留优先级最高一条 | A10 仅 `self_use` 被回填 |
| 退租中 | `biz_status='vacating'` | 符合 |
| 无法关联的招租（整租资产） | 被诊断视图暴露 | `listings_without_unit = 1`（T-A13） |
| 存量面积差异保留 | 可查 | `v_legacy_area_mismatch`：occupation_order#1 存 400 / 单元 600 |

**一个有价值的副产物**：迁移一次性暴露出 1 处真实数据缺陷——`T-A3` 存量标记为 `leased`，但实际只出租 300/1000（30%），正确状态应为 `partial_leased`。这类「状态与实际占用不符」的存量问题，旧模型无法检出（因为它只有资产级单状态位）。
