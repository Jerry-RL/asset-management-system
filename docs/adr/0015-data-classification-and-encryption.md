# ADR-0015: 数据分类分级与加密策略

- **状态**：Accepted
- **日期**：2026-08-26
- **决策者**：架构组、安全负责人

## 上下文

系统处理租户个人信息、合同与财务数据、权证扫描件、国资监管报表。SRS 要求「合规安全」，但原 NFR-SEC-004 过于笼统。国资项目对 **数据分类、加密、出境、审计** 有明确要求，需在架构层统一策略。

## 决策

1. 采用 **四级数据分类**（L1 公开 ~ L4 高敏），见 [数据安全设计说明书.md](../design/数据安全设计说明书.md) §2。
2. **传输**：生产强制 HTTPS（TLS 1.2+）。
3. **存储**：
   - PG 库盘加密 + L4 字段应用层 AES-256-GCM
   - OSS 私有桶 + SSE；备份加密
   - Redis 不存 L3/L4 明文
4. **密钥**：环境变量/KMS 托管；禁止入库与日志；定期轮换。
5. **展示**：API 层 `DataMaskingInterceptor` 按角色脱敏（手机、证件、银行卡）。
6. **出境**：生产业务数据 **存储与处理在境内**；LLM 默认私有化不出域（ADR-0008）。
7. **导出**：L3+ 导出水印 + `export_audit`；L4 默认禁止批量导出。
8. **保留**：监管类数据禁止物理删除；操作/安全日志 ≥ 3 年。

## 备选方案

| 方案 | 结论 |
|------|------|
| 仅 HTTPS 无字段加密 | 库泄露风险高 → 拒绝 |
| 全库同权无分级 | 不符数据安全法 → 拒绝 |
| 四级分类 +  selective 加密 | 可实施可审计 → **采纳** |

## 后果

- 正面：满足合规检查；Agent/导出/日志有统一基线
- 负面：字段加密影响等值查询（证件号查重需哈希索引列 `id_no_hash`）
- 缓解：敏感字段额外存 `HMAC-SHA256` 盲索引列用于精确匹配
