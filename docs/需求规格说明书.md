## 2. 项目概述

### 2.1 建设背景

面向地方国资国企、城投集团等主体，对经营性资产进行集中统一管理，覆盖资产登记、招租租赁、合同签约、收费财务、巡检维保、处置退出等全生命周期业务，实现资产运营线上化、数据化管理。

### 2.2 建设目标

系统建设应实现：

1. **资产盘清**：构建全域动态资产台账，账实相符、数据可追溯。
2. **经营提效**：招租—签约—收付—监管全流程数字化，提升出租率与收缴率。
3. **合规安全**：权证、合同、审批、日志留痕，满足国资监管要求。
4. **监管有效**：驾驶舱、地图、预警、报表支撑决策与风险管控。
5. **智能决策**：模板与自然语言驱动报告生成，指标可溯源可验证，服务管理员与决策层。

建设模式概括为：**资产一本账、布局一幅图、管理一张屏、资债全局览、决策一问清**。

### 2.3 系统组成

采用 **PC 管理后台 + 小程序用户端 + 小程序工作端** 三端一体化架构：

| 端 | 使用对象 | 主要场景 |
|----|----------|----------|
| PC 管理后台 | 资产管理人员、财务、审批人、系统管理员 | 台账维护、租控运营、合同审批、收费对账、报表分析、系统配置 |
| 小程序用户端 | 承租方租户 | 身份绑定、线上缴费、报修报事、招租报名、消息通知 |
| 小程序工作端 | 一线运维、外勤人员 | 任务处理、现场巡检、收费办理、催租张贴、合同审批 |

| 角色 | 说明 | 主要使用端 |
|------|------|------------|
| 系统管理员 | 组织架构、角色权限、系统参数、日志审计、智能模板与模型配置 | PC |
| 运营管理员 | 招租、租控、合同、租户、平台内容配置 | PC |

| 决策层/领导 | 经营看板、智能报告、监管摘要（只读+导出） | PC |
| 维修管理员 | 报修受理、维修公司、巡查、工单闭环 | PC |
| 审批人员 | 合同审批、招租审批、流程节点处理 | PC / 工作端 |

## 3. 系统总体描述

### 3.1 业务全景

资产全生命周期闭环（完善后，全量建设范围）：

```
资产接收/登记 → 权证与价值建档 → 租控与定价基准 → 招租/公开遴选
→ 签约审批 → 租金计划自动生成 → 履约收费 → 发票与对账
→ 巡检维修（SLA）→ 合同到期分支
    ├─ 续签 → 签约审批
    └─ 退租 → 清场验收 → 保证金结算 → 租控变空置 → 盘活任务 → 招租
→ 资产处置 → 档案归档
```

并行链路：

- 欠费：账单逾期 → 催缴等级升级（L1–L5）→ 回款或法务/清退 → 信用档案更新
- 经营：年度计划 → 执行数据采集 → 偏差分析 → 督办任务 → 招租/催缴/调价
- 业财：业务收款 → 银行对账 → 收入确认 → 凭证推送财务系统
- 合规：重大事项审批 → 备案材料包导出 → 监管留痕
- 处置：处置申请 → 审批 → 执行 → 已退出 → 档案归档
- 通知：业务事件 → 消息推送 → 待办处理 → 已读关闭

各阶段数据在「资产档案」中贯通；租控、账单状态仅由业务单据驱动变更（见 §4.24）。

### 3.3 约束与假设

1. 系统按 **同时在线 200 人** 规模设计，满足项目管理人员同步操作。
2. 业务操作响应流畅的前提为：甲方办公网络带宽充足、无防火墙限流、无运营商故障；网络类问题不归属系统故障。
3. 部署可采用云服务器或私有化部署，支持 Linux / Windows 常见操作系统。
4. V2.0 将 P0、P1、P2 全部纳入建设范围；实施可按 §4.25 分期交付，但验收以全量功能清单为准。
5. 设计稿中「预算管理」等 Tab 对应 §4.23.1 经营计划与预算模块。

### 4.23.1 经营计划与预算闭环 **[P1]**

**需求编号**：FR-PLAN-001 ~ FR-PLAN-004

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-PLAN-001 | 年度/月度经营计划 | 按公司、项目录入目标出租率、收缴率、经营收入、空置压降面积 |

### 4.23.2 定价与租金规则引擎 **[P0]**

**需求编号**：FR-PRICE-001 ~ FR-PRICE-006

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-PRICE-001 | 定价基准 | 资产维护评估租金、备案底价、市场参考价（关联评估申请） |
| FR-PRICE-002 | 计租方式 | 固定月租/年租/按面积/按套/面议（面议须审批后转固定） |
| FR-PRICE-003 | 递增与阶梯 | 按年递增比例或固定增幅；支持多年不同单价 |
| FR-PRICE-004 | 免租与保证金 | 装修免租天数/月数；保证金按倍数或固定额，联动合同模板 |
| FR-PRICE-005 | 缴费计划生成 | 合同审批通过后自动生成全周期缴费计划（收费大厅数据源） |
| FR-PRICE-006 | 低价合规校验 | 签约价低于底价时阻断或触发「超低价审批」 |
| FR-PRICE-007 | 首末月不足月折算 | 起租日非月初 / 退租日非月末时，首末两期按日折算；折算分母可配（当月自然日 / 固定 30 天），同一合同全程同一口径 |
| FR-PRICE-008 | 精度、舍入与尾差 | 每期金额保留 2 位小数；累计舍入尾差在末期一次性调整，保证全周期应收合计 = 合同总额精确相等 |

**折算规则**：免租期与首末非整月重叠时先扣免租再折算；递增/阶梯档位切换落在月内时按档位分段计后合并。

**闭环**：定价基准 → 招租挂牌 → 签约 → 规则引擎出计划（含折算/尾差）→ 收费出账 → 调价/减免回写。

### 4.23.6 催缴升级与法务协同 **[P1]**

**需求编号**：FR-DUN-ESC-001 ~ FR-DUN-ESC-004

| 等级 | 动作 | 触发条件（可配置） |
|------|------|-------------------|
| L1 | 短信/小程序提醒 | 到期前 N 天 |
| L2 | 催缴单 + 工作端张贴留痕 | 逾期 7 天 |
| L3 | 律师函/催告书模板导出 | 逾期 30 天 |
| L4 | 法务任务、诉讼登记 | 逾期 90 天或金额超阈值 |
| L5 | 提前解约/清退流程 | 协商失败 |

每条催缴记录必填：方式、时间、经办人、租户反馈、回款结果；未回款升级等级并更新信用档案。

**滞纳金/违约金规则（FR-DUN-LATE-001 ~ FR-DUN-LATE-004）**：

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-DUN-LATE-001 | 滞纳金规则配置 | 可配置日/月利率、起算日（到期日次日或宽限 N 天）、封顶（本金百分比或固定上限）、是否计入应收；按公司/合同类型设模板 |
| FR-DUN-LATE-002 | 自动计息 | 每日定时任务对未结清账单按规则滚动计息，生成滞纳金明细（金额、期间、利率快照）；金额随催缴等级联动展示于催缴单/律师函 |
| FR-DUN-LATE-003 | 滞纳金减免与豁免 | 与减免流程（FR-ADJ-*）联动；可单独减免/豁免滞纳金，超阈值升级审批；减免后计息基数同步调整并留痕 |
| FR-DUN-LATE-004 | 入账与法务依据 | 滞纳金计入欠费台账应收；退租结算（FR-VACATE-002）将「本金欠费 + 滞纳金」纳入抵扣顺序；律师函/催告书自动带出本金、滞纳金、起算日、已计天数 |

**计息规则**：仅对本金欠费计息（默认不复利）；结清/减免/终止/作废即停止计息；利率调整仅对调整后天数生效（利率快照留痕）。

### 4.23.28 期初数据迁移与建账闭环 **[P0]**

**需求编号**：FR-MIG-001 ~ FR-MIG-008

**定位**：系统切换（上线）的前置条件。将旧台账/旧系统/线下 Excel 中的在租业务与资金余额「平移」进新系统，保证上线首日「账实相符、一本账」可对外交付。缺本组需求则系统无法上线。

**总原则**：

1. 迁移与建账须有**统一基准日（Cutover Date）**，所有期初余额以该日冻结快照。
2. 迁移完成后须做**试算平衡**：期初在租合同应收合计 = 期初欠费合计 + 期初实收（历史）合计，不平不进试运行。
3. 期初数据标记来源 `source=迁移`，与上线后新增数据可区分、可追溯，业务人员不可手工修改（仅超管经审批修正，留痕）。

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-MIG-001 | 期初资产台账导入 | 导入项目、房产/土地资产、权证、抵押、价值信息；Excel 模板 + 校验（必填、编码唯一、面积/金额非负）；失败逐条报错可回退 |
| FR-MIG-002 | 期初在租合同导入 | 导入生效中合同：租户、资产、租期、租金类型与金额、缴费周期、当前缴费截止日、缴费状态；初始化租控=在租 |
| FR-MIG-003 | 期初账单与欠费余额 | 导入每个在租合同的历史应收、实收、**欠费余额**及账龄；生成期初欠费台账（联动 FR-DUN-* 催缴起算） |
| FR-MIG-004 | 期初保证金余额 | 按合同导入保证金实收余额、占用状态；区分「已收未退」「应退未退」 |
| FR-MIG-005 | 期初预收/预交余额 | 导入预收租金余额台账（按合同/租户），联动 FR-PREPAY-*；迁移后新账单可自动抵扣 |
| FR-MIG-006 | 期初租控状态初始化 | 按 FR-MIG-002~005 自动初始化租控：在租/占用/自用/处置中/退租中；无有效合同且非占用/自用 → 空置并填「空置原因」（FR-VACANT-001） |
| FR-MIG-007 | 期初催缴状态与信用档案 | 对期初欠费租户初始化催缴等级（L1–L5）与历史催缴记录；按 FR-TENANT-CREDIT-* 初始化信用分 |
| FR-MIG-008 | 迁移校验与试运行对账 | 迁移对账报告（期初合同数/面积/金额与旧系统核对）；「期初应收=期初欠费+期初实收」试算平衡；差异人工勾稽；通过后锁定基准日进入试运行 |

**闭环**：旧系统/线下台账 → 按基准日导出 → 模板校验导入 → 试算平衡 → 锁定进入试运行 → 上线后增量记账。

**验收要点**：任选一在租资产，其合同金额、欠费余额、保证金余额与新系统期初台账一致；期初欠费租户上线即入催缴队列且等级正确；试算平衡报告可导出且无未勾稽差异。

### 4.23.29 收款核销与分配闭环 **[P0]**

**需求编号**：FR-PAY-001 ~ FR-PAY-005

**定位**：补齐「收费大厅 / 收款记录」的核销算法。一笔收款如何匹配多张历史账单，决定「已缴/部分缴/待缴」账单状态机（§4.24.2）能否正确流转，也是退款冲正（FR-REF-*）与预收抵扣（FR-PREPAY-*）的基础。

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-PAY-001 | 核销策略配置 | 可配置核销顺序，默认 **FIFO（先欠先核）**；可选「指定账单核销」「按比例核销」；同一合同全程一致 |
| FR-PAY-002 | 收款与账单核销 | 一笔收款可拆分核销多张账单；支持全额与**部分核销**；部分核销后账单状态=部分缴，记录「已核金额/未核金额」 |
| FR-PAY-003 | 核销优先级与冲正联动 | 同一账单「本金 + 滞纳金」可配置核销顺序（默认先滞纳金后本金）；冲正（FR-REF-003）按原核销记录**逆序回退**账单状态 |
| FR-PAY-004 | 预收抵扣规则 | 预收余额（FR-PREPAY-001）在账单出账后按「到期先后」自动抵扣；抵扣生成核销流水，与收款核销共用同一核销台账 |
| FR-PAY-005 | 核销流水与对账 | 每笔核销生成不可变流水（收款单号、账单号、核销金额、时间、操作人）；作为收款记录、业财对账（FR-FIN-001）、发票核销（FR-INV-LC-002）的单一事实来源 |

**业务规则**：收款金额不得超过「可核销总额」（未核销本金 + 未核销滞纳金），超额转预收或原路退回（默认动作可配）；已全额核销账单不可再次核销；核销流水不可删改，仅可经冲正反向对冲；冲正后关联发票须联动红冲（FR-INV-LC-003）。

**闭环**：收款入账 → 按策略匹配账单 → 生成核销流水 → 账单状态流转 → 退款/冲正逆序回退 → 对账/发票联动。

**验收要点**：租户欠 B1=8,000（先到期）、B2=6,000（后到期），收款 10,000 → FIFO 下 B1 全额核销、B2 部分核销（欠 4,000）；冲正后两账单状态按逆序正确回退。

- 对外分享或监管用途的报告，支持 **人工确认/审批** 后发布（可配置）。

**设计参考**：智能中心-报告中心、HTML 预览页（待 UI 设计）

## 4.27 业务闭环总览与验收矩阵

> V2.2 起共 **十三条** 业务闭环，验收时须全部通过（见 §10.1）。

| # | 闭环名称 | 校验点（摘要） | 主要需求 |

| 5 | 监管闭环 | 重大事项可导出备案材料包 | FR-COMP-*、FR-TENDER-005 |
| 6 | 处置闭环 | 处置申请 → 审批 → 执行 → 已退出 → 备案 | FR-DISP-* |
| 7 | 占用闭环 | 占用申请 → 审批 → 占用 → 解除 → 空置 | FR-OCC-* |
| 8 | 业财闭环 | 收款 → 对账 → 收入确认 → 凭证 | FR-FIN-* |
| 9 | 发票闭环 | 收款 → 开票 → 核销 → 红冲 | FR-INV-LC-* |

| 12 | 通知闭环 | 业务事件 → 推送 → 待办 → 处理 | FR-NOTIF-*、FR-TASK-* |
| 13 | 自用闭环 | 自用申请 → 审批 → 自用 → 结束 → 空置 | FR-SELF-* |

> 组合/拆分租赁规则见 FR-MDM-*、FR-OPS-002；编码阶段在 DSD 细化算法。

**交叉规则**：

1. 租控状态仅由 §4.24.1 所列单据驱动。
2. 重大事项（低价、大额减免、处置）须走 FR-COMP-* 审批链。
3. 退款/红冲/冲正须双向联动账单、收款、发票、凭证。
4. 所有闭环关键节点须写操作日志（FR-COM-004）。
5. 收费计量以「不足月折算（FR-PRICE-007/008）+ 滞纳金（FR-DUN-LATE-*）+ 核销分配（FR-PAY-*）」三大算法为准，保证应收/实收/欠费口径一致。
6. 期初迁移（FR-MIG-*）是经营/业财/催缴闭环的上线前置，试算平衡通过后方可进入试运行。

### 5.8 数据安全（重点） **[P0]**

> **说明**：国资资产管理系统涉及租户个人信息、合同财务、权证影像与监管报表，**数据安全为最高优先级非功能需求**。技术落地见 [数据安全设计说明书.md](./design/数据安全设计说明书.md)、[ADR-0015](./adr/0015-data-classification-and-encryption.md)。

#### 5.8.1 分类分级

| 编号 | 要求 |
|------|------|
| NFR-DSEC-001 | 建立四级数据分类：L1 公开、L2 内部、L3 敏感、L4 高敏；字段级标注 |
| NFR-DSEC-002 | L3 及以上访问须 RBAC + 数据范围校验；越权返回 403 并记安全事件 |
| NFR-DSEC-003 | L4 高敏字段至少含：密码、身份证号、手机号、完整银行卡、密钥类配置 |

#### 5.8.2 加密与存储

| 编号 | 要求 |
|------|------|
| NFR-DSEC-004 | L4 字段应用层加密存储（AES-256-GCM 或同等）；密码单向哈希不可逆 |
| NFR-DSEC-005 | 数据库、对象存储、备份文件须加密；Redis 禁止存储 L3/L4 明文 |
| NFR-DSEC-006 | 密钥与证书由 KMS/环境变量托管，禁止写入代码库、业务表与日志 |
| NFR-DSEC-007 | 密钥定期轮换（JWT ≥90 天；加密主密钥 ≥1 年含重加密计划） |

#### 5.8.3 展示、导出与共享

| 编号 | 要求 |
|------|------|
| NFR-DSEC-008 | API 响应按角色脱敏展示（手机、证件、银行卡等）；无权限不返回 L4 明文 |
| NFR-DSEC-009 | L3 及以上数据导出须独立权限；导出文件含水印（导出人、时间、公司） |
| NFR-DSEC-010 | 每次 L3+ 导出记入导出审计（范围、条数、文件哈希） |
| NFR-DSEC-011 | L4 默认禁止批量导出；确需导出须审批 + 双人复核（可配置） |
| NFR-DSEC-012 | 向第三方（支付、短信、LLM）共享数据遵循最小必要原则并脱敏 |

#### 5.8.4 生命周期与合规

| 编号 | 要求 |
|------|------|
| NFR-DSEC-013 | 个人信息采集须告知同意（关联 FR-OP-002）；最小必要采集 |
| NFR-DSEC-014 | 生产业务数据 **存储与处理在中华人民共和国境内**；禁止未授权出境 |
| NFR-DSEC-015 | 合同、收款、权证、处置等监管类数据禁止物理删除；逻辑归档 + 长期可查 |
| NFR-DSEC-016 | 操作日志、安全事件、导出审计保留 ≥3 年；登录日志 ≥1 年 |
| NFR-DSEC-017 | 测试环境使用脱敏或合成数据；禁止复制生产 L3/L4 明文到开发环境 |

#### 5.8.5 备份、恢复与销毁

| 编号 | 要求 |
|------|------|
| NFR-DSEC-018 | 备份加密存储；灾备数据与生产同等安全级别 |

| 评估申请 | 机构、报告、定价基准回写 |
| 消息通知 | 事件、渠道、已读、业务单关联 |
| 期初迁移批次/导入日志 | 基准日、来源文件、校验结果、试算平衡状态（FR-MIG-*） |

### 8.2 数据保留

- 合同、收费、权证、日志等监管类数据长期保留，删除需权限与审计。
- 附件与扫描件与业务单据关联存储，支持版本追溯。

## 10. 验收标准（概要）

### 10.1 功能验收

1. 第 4 章及 §4.23 全量功能可验收，核心业务流程端到端跑通：
   - 资产建档 → 定价 → 招租/公开遴选 → 签约审批 → **自动生成缴费计划** → 收费/发票 → 巡检维修（SLA）→ 续签或 **退租清场/保证金结算** → 空置盘活 → 招租或处置退出
2. 三端数据一致：用户端缴费/签约/报修、工作端清场/抄表/收费、PC 台账同步。
3. 预警、任务、审批、催缴升级、日志按规则触发并留痕。
4. **十三条业务闭环校验**（必须全部通过，详见 §4.27）：

| 闭环 | 校验点 |
|------|--------|
| 经营闭环 | 任一在租资产：定价依据 → 合同 → 账单 → 实收 → 发票 |
| 空置闭环 | 任一空置资产：空置原因 → 盘活方案/任务 → 招租记录 → 签约或处置结果 |
| 退租闭环 | 任一退租：清场单 → 结算单 → 保证金处理 → 租控回写空置 |
| 风险闭环 | 任一预警/催缴：规则 → 触发 → 责任人 → 处理 → 关闭或升级 |
| 监管闭环 | 公开招租、低价出租、大额减免、处置可导出备案材料包 |
| 处置闭环 | 任一处置：申请 → 审批 → 执行 → 已退出 → 档案/备案 |
| 占用闭环 | 任一临时占用：申请 → 审批 → 占用 → 解除 → 空置 |
| 业财闭环 | 任一收款：收款记录 → 银行对账 → 收入确认 → 凭证 |
| 发票闭环 | 开票 → 核销勾稽 →（如需）红冲 |
| 退款闭环 | 退款申请 → 审批 → 冲正 → 账单/凭证/发票联动 |
| 评估闭环 | 评估申请 → 报告 → 定价基准 → 招租/签约校验 |
| 通知闭环 | 业务事件 → 消息推送 → 待办 → 处理关闭 |
| 自用闭环 | 自用申请 → 审批 → 结束 → 空置 |

5. **P2 专项**：电子签约全流程、无形资产生台账与摊销、智能定价建议可演示。
6. **智能服务专项 [P1]**：
   - 预置模板生成经营月报，HTML 在线预览可打开；
   - 报告指标可点击查看 Tool 溯源，数值与看板一致；
   - 越权用户无法通过 Agent 获取其他公司数据；
   - 未验证数据阻断 PPT/PDF 导出；
   - Agent 审计链路可查询。

### 10.2 非功能验收

1. 200 并发模拟下系统可完成主要业务操作，无明显失败或长时间阻塞。
2. 指定浏览器下界面与交互正常。
3. 权限隔离：不同角色仅可访问授权菜单与数据范围。
4. **数据安全（§5.8）**：
   - 生产全 HTTPS；L4 字段加密存储，API 默认脱敏展示；
   - 越权访问返回 403 并产生安全事件记录；
   - L3+ 导出含水印与导出审计；
   - 日志不含密码、证件号、完整手机号；
   - 备份加密且具备恢复演练记录；
   - Agent/LLM 生产不出域，脱敏网关生效。
